# UI·움직임 전면 개편 설계

작성일 2026-11-06. 시안: `design/prototypes/motion-hybrid.html`의 D, `design/prototypes/character-concepts.html`의 토끼 레이서.

## 왜 하는가

사용자 평가: 지금 앱은 "옛날 한컴타자연습 퀄리티"이고 파워포인트 같다. 캐릭터는 이미지 파일을 붙여 놓은 것 같고, 실제 앱을 구동하는 느낌이 없다.

원하는 수준은 카트라이더 러쉬플러스, 토스, 듀오링고, 말해보카, 주술회전 팬텀 퍼레이드의 부드러운 움직임과 완성도다. 캐릭터는 듀오링고처럼 화면마다 다른 동작으로 나와 실체감이 있어야 한다.

## 목표

1. 앱 전체가 반응하고 움직인다. 화면 전환, 버튼, 숫자, 목록이 모두 살아 있다.
2. 평소에는 토스처럼 차분하고, 결과가 뜨는 순간에만 레이싱 게임처럼 터진다.
3. 토끼 레이서가 화면마다 다른 동작으로 나오는 마스코트가 된다.
4. 체커기가 펄럭이는 로딩이 오른쪽 아래에 나온다.

## 하지 않는 것

- 점수 계산, 리그 계산, 차량 신호 수집을 바꾸지 않는다. `core/`와 시연 숫자는 그대로다.
- 새 기능을 넣지 않는다. 벨트 알림, 대결 만들기, 보험은 범위 밖이다.
- 진동은 넣지 않는다.

## 실패로 보는 것

- 움직임 때문에 버튼을 못 누르거나 기다려야 한다.
- 매번 같은 큰 연출을 봐야 해서 귀찮다.
- 시연 중 끊기거나 숫자가 틀린다.
- 주행이 시작됐는데 연출이 남아 있다.
- 아쉬운 날이 혼나는 기분을 준다.

## 지켜야 할 기존 규칙

- 주행 중 화면에는 점수, 순위, 감점이 없다. 토끼는 나오지 않는다. 움직임은 정차 중과 날씨가 바뀌는 순간에만 있다.
- 주행 제한이 시작되면 진행 중인 움직임을 즉시 끊고 주행 중 화면으로 간다.
- 아쉬운 날은 빨강을 쓰지 않고, 피트 보드로 고칠 것 하나만 보여 준다.
- 리플레이에 사건별 감점 숫자는 없다. 경로는 내 화면에만 나온다.
- 실명, 연락처, 이메일, 소속은 넣지 않는다.

## 사용자가 정한 것

- 방향은 D 타이밍 타워다. 어두운 바탕, 큰 기울임 숫자, 기울어진 순위 줄, 얇은 체커 띠를 쓴다.
- 캐릭터는 토끼 레이서다. 빨간 헬멧을 뚫고 나온 긴 귀, 노란 레이싱 슈트, 귀로 감정 표현.
- 앱 개편을 11/14 제출 시안보다 먼저 한다.
- 이미지 생성에 Orca, Codex, ChatGPT, Google Flow를 쓸 수 있다.
- 스프링 움직임에 AndroidX DynamicAnimation을 넣는다.
- 주차 상태의 결과 연출에 짧은 효과음을 넣는다.

## 시각 규칙

| 항목 | 값 |
|---|---|
| 바탕 | `#0D0F13`, 왼쪽 위에서 `#1C2028`로 은은한 빛 |
| 강조 | 노랑 `#FFC52E` 하나. 출발 신호등에만 빨강 |
| 글자 | 흰색 `#F4F4F1`, 보조 `#8A909B` 이상. 본문 대비 4.5:1 |
| 글꼴 | Pretendard, 숫자는 Saira Condensed 기울임 |
| 형태 | 순위 줄과 주요 버튼은 기울어진 모서리 |

아스팔트 질감, 금속 숫자, 빛줄기, 불꽃과 비 배경은 없앤다. 쓰이지 않게 된 View는 삭제한다.

## 움직임 규칙

공용 값을 한 곳에 두고 모든 화면이 쓴다.

| 이름 | 시간 | 쓰는 곳 |
|---|---|---|
| 빠름 | 120ms | 버튼 눌림 |
| 보통 | 240ms | 상태 변화, 탭 전환 |
| 느림 | 420ms | 화면 전환, 줄 이동 |

- 도착은 감속, 위치 이동은 살짝 넘어갔다 돌아오는 스프링을 쓴다. 스프링은 DynamicAnimation의 `SpringAnimation`으로 만든다. 나갈 때는 들어올 때보다 짧게 한다.
- 목록은 한 줄씩 40ms 간격으로 들어온다.
- `transform`과 투명도만 움직인다. 레이아웃 크기를 움직이지 않는다.
- 움직임이 끝나야 값이 맞는 구조를 만들지 않는다. 최종 상태를 먼저 정하고, 언제 끊겨도 최종 상태로 간다.
- 움직이는 중에도 버튼이 눌린다. 결과 연출은 화면을 누르면 끝 상태로 건너뛴다.
- 시스템 애니메이션 배율이 0이면 움직임 없이 최종 상태를 보여 준다.

## 화면별 내용

| 화면 | 움직임 | 토끼 |
|---|---|---|
| 이긴 날 결과 | 로딩 → 출발 신호등 5개 → 소등 → 속도선과 점수 카운트 → 착지 → 내 줄 추월 → 정보 등장 | 체커기 들고 점프 |
| 아쉬운 날 결과 | 신호등 없음. 로딩 → 점수 차분히 등장 → 피트 보드 | 귀를 늘어뜨리고 보드를 듦 |
| 3km 미만 카드 | 로딩 없이 차분히 등장 | 다음에 보자고 손짓 |
| 리그 | 버튼 위치에서 화면이 퍼지는 전환, 줄이 차례로 등장, 탭 전환 시 줄 교체 | 구석에서 승급 라인 가리킴 |
| 리플레이 | 경로가 그려지며 차 점이 달리고, 사건이 시간순으로 뜸 | 무전으로 안내 |
| 주간 리포트 | 막대가 자라고 순위 선이 그려지며 평균 점수 카운트 | 차트를 보며 끄덕임 |
| 차종 선택·배치 | 선택지가 차례로 등장, 고르면 눌림과 전환 | 손 흔들며 맞이 |
| 위치 동의 | 차분한 등장 | 지도를 듦 |
| 주행 중 | 기존 규칙 유지. 색과 글꼴만 새 규칙으로 | 없음 |

추월 횟수는 기존 순위 변화 값을 쓴다. 한 칸씩 올라가며 순위 숫자도 함께 바뀌고, 최대 3칸까지만 움직이고 나머지는 바로 건너뛴다.

## 연출 횟수

- 큰 연출은 트립이 끝나 P단으로 바뀐 그 결과에서 한 번만 나온다. 시연 각본 주행도 같다.
- 앱을 다시 열거나 리플레이에서 돌아오면 차분한 등장만 나온다.

## 로딩

- 체커기는 오른쪽 아래에 나오고 `기록 집계 중` 문구가 붙는다. 토끼의 로딩 동작과 함께 쓴다.
- 결과 데이터는 바로 준비되므로 연출 시간은 최대 1.5초로 하고, 화면을 누르면 건너뛴다.
- 앱 시작 때도 같은 깃발을 쓴다.

## 효과음

- 주차 상태의 결과 연출에서만 난다. 신호등 소리, 추월, 승리 등 짧은 소리 3~4개만 쓴다.
- 아쉬운 날은 큰 소리를 내지 않는다. 필요하면 부드러운 소리 하나만 쓴다.
- 주행 중에는 절대 나지 않는다. 주행 제한이 시작되면 재생 중인 소리도 멈춘다.
- 내비 안내와 음악을 방해하지 않도록 오디오 포커스를 지킨다. 포커스를 못 받으면 소리 없이 진행한다.
- 큰 연출을 건너뛰면 남은 소리도 내지 않는다.
- 음원은 직접 합성하거나 사용권이 확실한 것만 쓰고, 출처를 `design/README.md`에 적는다.
- PT 대회장에서 소리가 나오는지는 리허설 때 확인한다. 소리가 나지 않아도 연출은 그대로 동작해야 한다.

## 토끼 만드는 법

1. Flow, ChatGPT로 기준 그림을 뽑아 생김새를 확정한다. 슈트, 헬멧, 귀 비율을 사용자가 고른다.
2. 앱에는 부위를 나눈 벡터로 넣는다. 머리, 귀 2개, 몸, 팔, 다리, 표정을 따로 움직인다.
3. 기존 시안의 뼈대 구조를 쓴다.

통째로 된 이미지로는 귀와 표정을 따로 움직일 수 없어서 벡터 부위로 간다. 벡터로 만든 토끼의 품질이 부족하면 Rive를 다시 검토한다. Rive는 전용 편집기 작업이 필요해서 처음부터 쓰지는 않는다. 필요한 동작은 대기, 승리, 추월, 피트 보드, 라디오, 로딩, 맞이, 끄덕임, 가리키기다.

## 코드 구조

- `ui/motion/`: 움직임 값, 화면 전환, 숫자 카운트, 추월 순서, 효과음 재생.
- 새 의존성은 `androidx.dynamicanimation:dynamicanimation` 하나다.
- `ui/view/RabbitView.kt`: 토끼 그리기와 동작.
- `ui/view/FlagLoaderView.kt`: 체커기 로딩. `CheckerFlagView`를 대체한다.
- 화면 파일은 지금처럼 나눠 둔다. `MainActivity.show()`가 전환을 맡고, 주행 제한은 여기서 끊는다.
- 판단이 들어가는 것은 순수 함수로 두고 단위 테스트를 남긴다. 추월 단계 계산, 큰 연출 여부, 끊겼을 때의 최종 상태가 대상이다.

## 작업 순서

1. 기반: 움직임 값, 새 색과 글꼴, 화면 전환, 체커기 로딩.
2. 결과 화면: 이긴 날, 아쉬운 날, 3km 미만.
3. 토끼: 기준 그림, 벡터 부위, 동작.
4. 나머지 화면: 리그, 리플레이, 리포트, 차종 선택, 위치 동의, 주행 중.
5. 앱 캡처 기준으로 제출 시안 교체.

한 단계씩 main에 병합할 수 있어야 한다. 단계 사이에도 main은 에뮬레이터에서 돌아간다.

## 제출 일정과의 관계

앱 개편을 먼저 한다. 11/13까지 5단계가 끝나면 새 시안을 내고, 끝나지 않으면 기존 시안으로 11/14에 제출한다. 마감 전에는 재제출도 가능하다. 기획서의 캐릭터 설명이 바뀌는지는 제출 전에 확인한다.

## 완료 기준

- 단위 테스트와 빌드 통과.
- 에뮬레이터에서 모든 화면 확인. 시연 92점, 64점의 숫자가 기존 확인 목록과 같다.
- 결과 연출 중 주행을 시작하면 바로 주행 중 화면으로 간다.
- 연출 중 빠르게 눌러도 앱이 죽지 않고 최종 값이 맞는다.
- 애니메이션 배율 0에서 모든 화면이 정상이다.
- 주행 중에 효과음이 나지 않고, 주행이 시작되면 재생 중인 소리가 멈춘다.
- 오디오 포커스를 못 받아도 연출이 정상으로 끝난다.
- 에뮬레이터 `dumpsys gfxinfo`에서 결과 연출의 끊긴 프레임 비율을 기록하고 사용자가 눈으로 확인한다.
