# 리그 포인트 정산과 포인트 상점 설계

작성일: 2026-11-07

## 왜 만드는가

안전운전이 앱 안의 점수로 끝나지 않고 현대차그룹의 실제 서비스와 상품으로 돌아온다고 느끼게 한다. 기준은 네이버 포인트나 토스 포인트처럼 "모으면 실제로 쓸 수 있는 것"이다. 시즌이 끝날 때 확실한 보상을 받고, 다음 쿠폰이라는 목표가 생겨 다음 달에도 안전하게 달릴 이유가 있어야 한다.

## 목표

- 월간 시즌 정산 때 거리, 점수, 티어로 포인트를 지급한다.
- 앱을 열면 전체 화면 연출로 보상을 크게 보여 준다.
- 토끼가 운영하는 상점에서 목표 쿠폰을 정하고, 포인트를 쿠폰으로 교환한다.
- 교환한 쿠폰을 쿠폰함에서 실제 쿠폰처럼 본다.
- 12/3~4 PT에서 달이 바뀌길 기다리지 않고 정산부터 교환까지 시연한다.

## 하지 않는 것

- 실제 결제, 지급, 쿠폰 발급, 쿠폰 사용 처리
- 블루멤버스 포인트 연동(기획서의 향후 계획으로만 둔다)
- 포인트 소멸
- 서버 저장. 다른 앱 데이터처럼 기기에 저장한다.
- 재난 안내, 상황별 주의사항, 초보 꿀팁. 이 세 기능은 별도 설계로 다룬다.

## 실패로 보는 경우

- 포인트가 두 번 지급되거나, 교환 중 앱이 꺼져 포인트만 사라진다.
- 시연 중 화면 숫자가 계산식과 다르다.
- 주행 중 포인트나 상점 화면이 보인다.
- 시연용 쿠폰을 실제 쿠폰으로 오해하게 만든다.
- 포인트를 받으려고 불필요하게 더 운전하게 만든다.
- 평균이 낮은 운전자가 혼나는 느낌을 받는다. 앱의 격려하는 말투를 지킨다.

## 포인트 계산

월 정산 포인트 = 거리 포인트 × (1 + 점수 가산) × 티어 배율

- 거리 포인트: 해당 시즌 유효 트립의 km 합계 × 1P(10km당 10P). 3km 미만 트립 제외, 시즌 평균 계산과 같은 유효 트립을 쓴다. 월 1,000km까지만 인정한다.
- 점수 가산: 시즌 평균 70점 미만 0%, 70 이상 80 미만 +10%, 80 이상 90 미만 +30%, 90 이상 +50%. 70점 미만도 거리 포인트는 받는다.
- 티어 배율: 브론즈 1.0, 실버 1.2, 골드 1.5, 플래티넘 2.0, 다이아 2.5
- 그 시즌을 달린 티어의 배율을 쓴다. 정산으로 승급이나 강등되어도 지난 시즌 보상은 바뀌지 않는다.
- 소수점은 곱셈을 모두 끝낸 뒤 한 번만 반올림한다(0.5는 올림).

검증 예시(단위 테스트로 남긴다):

| 티어 | 거리 | 평균 | 결과 |
|---|---|---|---|
| 브론즈 | 500km | 75 | 550P |
| 브론즈 | 50km | 95 | 75P |
| 브론즈 | 500km | 95 | 750P |
| 다이아 | 500km | 75 | 1,375P |
| 다이아 | 50km | 95 | 188P |
| 골드 | 640km | 88.8 | 1,248P |
| 다이아 | 1,200km | 95 | 3,750P |
| 브론즈 | 300km | 60 | 300P |

## 정산 동작

- 기존 `SeasonSettlementStore.settleIfNeeded`와 `TierMovement.settleSince` 흐름에 붙인다. 시즌, 티어, 포인트, 표시할 정산 결과를 한 번의 `commit`으로 저장해 두 번 지급되지 않게 한다.
- 여러 달을 건너뛰었으면 달마다 그 달의 티어로 계산해 합치고, 화면은 한 번만 보여 준다.
- 유효 트립이 없는 달은 0P이고, 전체 합계가 0P이면 연출 없이 기존 안내만 띄운다.
- 앱을 연 시점이 주행 중이면 연출을 미룬다. 주차로 트립 결과 카드가 뜨는 경우 결과 카드를 먼저 보여 주고, 카드를 벗어나는 순간 정산 화면을 띄운다(설계자 판단). 결과 카드 없이 주차하면 바로 정산 화면을 띄운다.
- 정산이 있는 앱 시작은 기존 `!settled` 분기처럼 결과 카드를 건너뛰고 정산 화면으로 간다. 정산 화면을 닫으면 리그로 간다.
- 정산 화면은 시즌마다 한 번만 자동으로 뜬다. 표시 여부를 함께 저장해 앱이 꺼져도 다시 지급되지 않고, 못 본 화면은 다음 실행 때 보여 준다.

## 정산 화면 (A안 시상대)

시안: `.superpowers/brainstorm/1162-1794034235/content/settlement-layout.html`의 A안.

- 앱을 열면 전체 화면으로 시즌 이름, 티어, `+1,248P`를 크게 보여 준다. 숫자가 올라가고 효과음이 나며 토끼가 축하한다.
- 티어 배율 태그, 거리와 점수 가산 한 줄, 내 포인트 합계를 보여 준다.
- 승급한 달은 같은 화면에 승급 소식을 함께 넣는다. 강등은 기존처럼 격려하는 말투로 쓴다.
- 버튼: `포인트 상점 보기`, `리그로 가기`
- 평균 70점 미만의 달에도 같은 화면을 쓰되 "다음 달엔 보너스에 도전해 봐요" 같은 격려 문구를 쓴다.
- 여러 시즌을 합친 정산은 합계와 "N개 시즌 합산"만 표시하고, 티어 배율 태그와 거리·가산 줄은 숨긴다(설계자 판단). 한 줄로 합계를 설명할 수 없어 화면 숫자가 계산식과 어긋나 보이는 일을 막기 위해서다.

## 포인트 상점 (토끼 피트샵)

시안: `.superpowers/brainstorm/1162-1794034235/content/shop-counter.html`. 사용자가 이 구성을 승인했다. 배경 원본 `.forge/shop-bg/out1/generated.png`은 저장소의 `design/`으로 옮기고 앱에는 축소본을 넣는다. `토끼 피트샵` 이름과 말풍선 문구는 예시이며 구현하며 다듬어도 된다.

- 왼쪽: 픽셀아트 정비소 벽, 토끼(기존 `welcome` 프레임 확대, 하반신은 카운터로 가림), 말풍선, 카운터 앞면의 목표 게이지
- 오른쪽: `상점`·`쿠폰함` 탭, 상품 목록, 시연용 안내 문구
- 말풍선은 상황에 맞게 바뀐다(목표까지 남은 포인트, 교환 가능, 응원).
- 상품을 누르면 목표로 정하거나, 포인트가 충분하면 교환할 수 있다.
- 목표가 없으면 가장 싼 미교환 쿠폰을 안내한다.
- 교환 뒤 목표였던 쿠폰은 목표에서 해제된다. 같은 쿠폰을 여러 번 교환할 수 있다.

상품(1P = 10원 가치로 둔 시연용 가정, 코드 한 곳에 표로 둔다):

| 상품 | 가격 | 대상 |
|---|---|---|
| 충전 크레딧 1만 원 | 1,000P | 전기차 |
| 정비 쿠폰 1만 원 | 1,000P | 전체 |
| 정비 쿠폰 5만 원 | 5,000P | 전체 |
| 엔진오일 교환권 | 10,000P | 내연기관차 |

대상은 `VehicleProfile.powertrain`으로 가르고, 대상이 아닌 상품은 숨긴다. 시연 모드는 시연 리그와 같은 아이오닉 5(전기차)로 보므로 엔진오일 교환권이 나오지 않는다. 승인 시안의 네 줄 목록은 구성 참고용이다. 차종을 바꿔 목표 쿠폰이 대상에서 빠지면 목표를 해제한다(설계자 판단).

## 교환과 쿠폰함

- 교환 전에 앱 안에서 한 번 더 확인한다. 시스템 알림창은 쓰지 않는다.
- 포인트 차감과 쿠폰 생성은 한 번의 `commit`으로 저장한다. 잔액이 모자라면 교환되지 않는다.
- 교환하면 토끼가 축하하며 쿠폰을 건네는 연출을 보여 주고 쿠폰함으로 이어진다.
- 쿠폰함은 금액, 유효기간(발급 후 90일), 바코드를 보여 주고 바코드에 시연용이라고 표시한다. 기간이 지난 쿠폰은 만료로 표시한다.
- 바코드는 쿠폰 ID로 그린 가짜 그림이다. 쓸 수 있는 코드처럼 보이지 않게 시연용 표시를 겹친다.

## 앱 안의 입구와 제약

- 리그 화면에 내 포인트와 상점 버튼을 둔다. 정산 화면 버튼으로도 들어간다.
- 주행 중에는 상점, 쿠폰함, 정산 화면을 열지 않는다. 열려 있다가 주행이 시작되면 기존처럼 주행 중 화면으로 바뀐다.
- 빨강은 출발 신호등에만 쓴다. 색은 #0D0F13, #FFC52E와 기존 토큰을 쓰고, 글꼴은 Pretendard와 Saira Condensed를 쓴다.

## 시연

- 시연 모드에서 정산 장면을 바로 재생하는 버튼을 기존 시연 도구에 추가한다.
- 시연 정산은 끝난 시즌인 `10월 시즌`으로 표시한다. 시연 리그가 진행 중인 11월이어서 `리그로 가기`를 눌러도 모순이 없다(설계자 판단). 숫자는 골드, 640km, 평균 86.4점, 1,248P다. 평균은 진행 중인 11월 평균 88.8점과 구분되게 바꿨고 결과 포인트는 같다.
- 시연 시작 상태는 잔액 3,420P(정산 포함), 목표 `정비 쿠폰 5만 원`, 쿠폰함 1장이다.
- 시연 포인트와 쿠폰은 메모리에만 두고 실제 저장값과 섞지 않는다. 재생 버튼을 다시 누르거나 시연 모드를 다시 켜거나 앱을 재시작하면 시작 상태로 돌아가 리허설을 반복할 수 있다(설계자 판단). 시연 모드를 끄면 실제 잔액으로 돌아간다.
- 리허설 기록 때문에 실제 정산 화면이 뜰 수 있으므로, PT 전 앱을 한 번 열어 정산을 끝내 두는 것을 리허설 체크 항목에 넣는다(설계자 판단).

## 일정

- 11/13까지 앱에 완성되어 main에 병합되면 기획서 v6와 제출 시안에 상점을 넣어 11/14에 제출한다.
- 11/13까지 안 되면 기획서 v5와 기존 시안 6장으로 제출하고, 12/3 PT 전까지 마무리한다. v5에 이미 `보상 연계: 현대자동차 멤버십 포인트, 정비·충전 할인 쿠폰`이 있어 크게 어긋나지 않는다.
- 제출 일정이 위험해지면 11/14 제출을 우선한다.

## 구조 제약

- 포인트 계산은 순수 함수로 분리해 단위 테스트를 남긴다(예: `core/calculator/PointCalculator.kt`).
- 화면은 파일을 나눈다(예: `ui/SettlementScreen.kt`, `ui/ShopScreen.kt`).
- 새 외부 라이브러리는 추가하지 않는다.
- 작업은 브랜치에서 하고 사용자 확인 후 main에 병합한다. 에뮬레이터는 GPU host, cold boot만 쓴다.

## 만드는 사람에게 맡기는 것

- 숫자 올라가는 속도, 효과음 선택, 연출 타이밍
- 말풍선 문구 세부 표현
- 공구 배경의 크기와 잘라 쓰는 위치
- 저장 형식(기존 SharedPreferences 방식을 우선)
