# 시작 연출과 홈 화면 설계 (2026-11-08)

## 왜

사용자: "기본 화면, 기본 홈이 없고 처음 시작할 때 너무 갑작스럽게 뜬다." 지금은 앱을 켜면 체커기 로더("준비 중")가 오른쪽 아래에 잠깐 뜨고 곧바로 리그 순위 화면이 나온다. 앱의 얼굴이 되는 출발점이 없다.

목표는 두 가지다.
1. 켜는 순간이 의도된 연출로 느껴질 것 (갑작스럽지 않게).
2. 내 상태를 한눈에 보고 원하는 기능으로 가는 홈이 있을 것.

사용자가 브라우저 시안 3개 중 **A. 패독 차고**를 골랐다. 시안 원본: `.superpowers/brainstorm/1193-1794111701/content/home-options-v3.html` (저장소 밖, 참고용).

## 결정된 것 (사용자 확인)

### 시작 연출 (스플래시)
- 어두운 바탕(#0D0F13) 가운데에 새 앱 아이콘(방패 속 토끼)이 튀어나오고(작게 → 살짝 크게 → 제자리), `SAFETY LEAGUE` 글자가 넓은 자간에서 모이며 나타나고(LEAGUE는 노랑), 아래 얇은 노란 바가 찬다. 끝나면 사라지고 홈이 나온다.
- 길이 약 2초. 앱이 새로 시작될 때만(onCreate, savedInstanceState == null) 나온다. 다른 앱에 갔다 돌아올 때는 없다.
- 주행 중(restricted)이면 연출 없이 주행 중 화면.

### 홈 화면 (새 Screen.HOME)
- 앱의 출발점. 지금 `show(Screen.LEAGUE)`로 시작하던 자리를 홈으로 바꾼다.
- 배경: 패독 그림 `scene_paddock`(어둡게).
- 왼쪽: 토끼(인사 동작 `Pose.WELCOME` 계열)와 말풍선 인사말.
- 오른쪽 위 시즌 카드: "N월 시즌 · 차종 리그", 티어 벨트(`tierBelt(tier)`), 큰 순위 `P3`, 티어 이름, 승급까지 남은 정도(`promotionText`), 시즌 남은 날, 지난 주행 점수, 포인트.
- 그 아래 큰 메뉴 4칸(2×2): **리그 순위, 주간 리포트, 피트샵, 안전 가이드**. 칸마다 한 줄 정보.
- 열릴 때 카드가 아래에서 차례로 올라온다(기존 `ScreenTransition.stagger` 재사용).

### 흐름
- 안 본 결과 카드나 달 넘김 정산이 있으면 스플래시 다음에 그 화면이 먼저 나오고, 닫으면(뒤로) 홈으로 간다.
- 리그, 리포트, 피트샵, 안전 가이드에서 뒤로 가면 홈. 홈에서 뒤로 가면 기본 동작(앱을 내림).
- 첫 사용자는 지금처럼 차량 선택 → 위치 동의를 먼저 하고, 끝나면 홈.
- 리그 화면의 피트샵·가이드 바로가기(`btn_shop`, `btn_guide`)는 홈과 겹치므로 리그에서 뺀다.

## 목표가 아닌 것
- 주행 중 홈 표시 (주행 중 화면 규칙 그대로: 점수·순위 없음).
- 하단 탭 바 같은 전역 내비게이션 (C안 요소, 고르지 않음).
- 새 캐릭터 그림 제작. 토끼는 앱의 기존 스프라이트만 쓴다.
- 점수 산식, 승급 규칙, 포인트 값 변경.

## 하면 실패인 것
- 시작 연출이 길거나 매번 나와서 귀찮아지는 것 (2초, 새로 시작할 때만).
- 주행 중에 홈이나 시즌 숫자가 보이는 것.
- 안 본 결과 카드나 정산이 홈에 묻혀 놓치는 것.
- 홈 숫자가 리그·리포트·상점 화면 숫자와 다른 것 (같은 계산 함수를 쓴다).
- 빨강 사용 (빨강은 출발 신호등에만).

## 제약
- `AGENTS.md` 규칙: 화면별 파일 분리(`ui/HomeScreen.kt`, `view_home.xml`), 순수 로직은 단위 테스트, Ponytail Lite(있는 것 재사용, 최소 diff).
- 화면 크기: DesignCanvas 1280×720dp 기준.
- 시연 모드(`demoMode`)에서는 다른 화면처럼 `DemoData` 숫자(11월 시즌, 골드, P3 등)를 쓴다. 시연 바에 홈 탭을 추가한다.
- 애니메이션은 `animationsEnabled()`가 거짓이면 생략하고, `motion`(MotionScope)에 등록해 화면 전환 시 `finishAll()`로 끝난다.

## 내가 정한 것 (사용자 확인 전 기본값, 플랜에서 바꿔도 됨)
- **인사말:** 상황에 따라 바뀐다. 우선순위: 승급권이면 "승급권이에요! 이대로만 가요", 지난 주행이 오늘이면 점수에 맞는 한 줄(70 이상 칭찬, 미만은 혼내지 않는 말투), 아니면 시간대 인사(아침/낮/저녁). 순수 함수로 두고 테스트한다.
- **메뉴 칸 한 줄 정보:** 리그 = "같은 차종 N명" 또는 순위가 없으면 "첫 주행을 마치면 순위가 나와요", 리포트 = 이번 주 평균 점수(없으면 "이번 주 주행 기록 없음"), 피트샵 = "쿠폰 N장" 또는 "포인트 NP", 가이드 = 날씨 추천 카드가 있으면 "오늘은 빗길 카드", 없으면 "재난·상황·초보 꿀팁". 리포트 쪽 "지난주보다 +N점"처럼 이미 계산된 값이 있으면 그것을 쓴다.
- **기존 체커기 로더 "준비 중":** 스플래시가 대신하므로 앱 시작 때는 띄우지 않는다(다른 곳의 "기록 집계 중"은 그대로).
- **스플래시 구현:** 액티비티 안 오버레이 뷰(activity_main.xml 최상단 레이어). Android 12 SplashScreen API는 쓰지 않는다(아이콘만 보여 줄 수 있고 글자·바 연출이 안 됨). 시스템 시작 창의 배경은 테마의 `windowBackground`를 #0D0F13으로 맞춰 흰 화면 깜빡임을 없앤다.
- **스플래시와 데이터 준비:** 스플래시 동안 홈을 미리 만들어 두고, 연출이 끝나면 덮개만 걷는다. 스플래시 도중 터치하면 바로 건너뛴다.
- **효과음:** 없음. 결과 순간에만 소리를 내는 기존 원칙을 따른다.
- **화면 안 버튼:** "뒤로" 성격의 버튼(리포트·상점·가이드의 뒤로 버튼, 결과 카드와 정산의 닫기 성격 버튼, 차량 설정·위치 동의 완료)은 홈으로 간다. "리그"라고 적힌 버튼은 그대로 리그로 간다. 달 넘김 정산으로 돌려보내는 `redirectToSettlement`는 HOME으로 갈 때도 걸리게 한다.
- **데이터가 없을 때 시즌 카드:** 순위는 `–`(기존 표기), 승급 줄은 `promotionText`의 "첫 주행을 마치면 순위가 나와요", 지난 주행은 "아직 주행 기록이 없어요", 인사말은 시간대 인사. 첫 사용자가 처음 보는 상태라 칸을 숨기지 않고 자리를 유지한다.
- **스플래시 아이콘:** 2026-11-08에 만든 현재 앱 아이콘 `mipmap/ic_launcher_foreground`(원본 `design/icon/icon-foreground-432.png`)를 그대로 쓴다. 새 그림은 없다.

## 빌더에게 맡기는 것
- 레이아웃의 정확한 dp 값, 글자 크기, 카드 색(기존 `ink_glow`, `ink` 등 색 재사용).
- 토끼 동작 프레임 선택과 위치(시안처럼 왼쪽, 말풍선 위).
- 시즌 카드 숫자를 기존 `standing()`, `promotionText()`, `wallet`, `repository.latestCompletedTrip`에서 가져오는 방식.
- `ScreenFlow.kt`의 `resumeAction`/`backTarget`과 `Resume.LEAGUE`를 홈으로 바꾸는 범위와 테스트.

## 확인 방법
- 단위 테스트: 인사말 선택, `backTarget`/`resumeAction` 변경.
- 에뮬레이터: 새로 켜기(스플래시 → 홈), 안 본 결과가 있을 때(스플래시 → 결과 → 뒤로 → 홈), 첫 사용자 흐름, 각 메뉴 왕복, 시연 모드 홈, 다른 앱 다녀오기(스플래시 없음), 주행 중 켜기(주행 중 화면).
- 제출 시안 `design/submission/`에 홈 화면 캡처를 추가할지는 끝난 뒤 사용자에게 묻는다.
