- 제안: 판정과 표시를 하나로 맞춘다. 예를 들어 표시를 버림(`floor`)으로 하거나, 소수 첫째 자리까지 보여 주거나, 점수를 정수로 저장해 그 값으로 판정한다. 69.5·69.9·70.0 경계 테스트를 추가한다.

### H2. 운전 제한이 P 전에 풀리면 이전 트립 결과 카드가 뜬다 — [확인·코드 + 추정]
- 위치: `ui/MainActivity.kt:212-223`
- 스펙: 결과 카드는 GEAR_SELECTION이 P로 바뀔 때 뜬다. 주행 중에는 점수 화면을 띄우지 않는다.

- 제안: 제한이 풀렸을 때 `service?.isTracking == true`이면 주행 중 화면을 유지한다. 결과 카드는 `onTripResult`(P 신호)에서만 연다.

### H3. 에코 점수가 마지막 순간 전비 하나로 정해진다 — [확인·실행]
- 위치: `core/collector/TripCollector.kt:203`, `core/collector/VehicleSignals.kt:39-40`, `core/calculator/ScoreCalculator.kt:40-42`
- 스펙: 같은 차종 평균 대비 전비/연비.
- 실제 동작: `onEfficiencyChanged`가 올 때마다 `efficiency = value`로 덮어쓴다. 주석에 따르면 이 신호는 "순간 전비"다. 주차 직전 감속·정지 구간의 값 하나가 트립 전체의 에코 점수가 된다. 값이 0 이하면 리그 평균으로 처리되어 10점이다.
- 재현 값: 트립 내내 7.0 km/kWh였다가 주차 직전에 3.0이 한 번 오면 → 에코 **0.0**(트립 평균으로는 20점 만점).
- 제안: 거리 가중 평균을 쓴다(Δ주행거리 × 순간값 누적 ÷ 총 거리). 가능하면 트립 시작과 끝의 배터리·연료 소모량으로 계산한다. 0 이하나 비정상 값은 버린다.

### H4. 출발 직후 가속도가 부풀려진다 — [확인·실행]
- 위치: `core/collector/TripCollector.kt:99`(`anchorSpeed = lastSpeed; anchorMs = t`), `:117-122`
- 스펙: 부드러움은 10km당 급가속·급감속 횟수다.
- 실제 동작: 트립이 시작되는 표본에서 기준 속도는 "직전 속도(보통 0)", 기준 시각은 "지금"이 된다. 그래서 첫 0.5초 구간의 가속도가 (시작 속도 ÷ 0.5초)만큼 커진다.
- 재현 값: 정차 0 → D → 0.6 m/s(t) → 1.3(t+250ms) → 2.0(t+500ms). 실제 가속도는 2.8 m/s²인데 (2.0−0)/0.5 = 4.0으로 계산되어 **급가속 1회**가 된다. 주석에 따르면 보통 출발은 1.5~2.5 m/s²인데, 이 값에 약 1~1.2 m/s²가 더해져 기준 3.0을 넘기 쉽다.
- 제안: `startTrip`에서 `anchorSpeed = speedMps`(시작 표본)로 둔다. 또는 기준 시각을 직전 표본 시각으로 둔다. 실측 출발 로그로 테스트를 추가한다.

- 지역·친구 탭: `League.region`만 있고 탭은 없다. 작은 인원 순위선(L2)을 같이 봐야 한다.
