# 작업 지시서: 실제 점수 리그 연결 + 차종 인식·리그 배치

브랜치 `codex/league-real-score`, 작업 폴더 `safety-league-codex/`. 시작 전 `docs/CODEMAP.md`를 본다.
이 작업에서는 `core/`를 고쳐도 된다. 단, `ScoreCalculator`의 배점과 감점 계수는 바꾸지 않는다.

## 목표
1. 실제로 달린 트립이 내 순위·승급 라인·연속 기록을 바꾼다.
2. 첫 실행 때 차종을 정하고 「아이오닉 5 리그 브론즈 단계에 배치되었습니다」 화면을 보여 준다.
3. 시연 모드의 각본 화면(92점/64점, 골드 리그 P125)은 지금과 같게 유지한다.

## 지금 문제 (코드에서 확인함)
- `MainActivity.showResultWin/showResultLow/showLeague`가 실제 트립에도 `DemoData.ranks`, `neighbors`, `lowBoard`와 고정 날짜를 쓴다.
- `TripRepository.getAllTrips()`가 `DemoData.trips`와 실제 트립을 섞는다. 그래서 `getStreak`도 시연 트립을 센다.
- `TripTrackingService.onTripFinished`가 시연 각본 주행도 `saveTrip`으로 저장해서 실제 기록에 섞인다.
- 결과 카드 두 곳이 경로가 없을 때 `ifEmpty { DemoData.route }`로 가상 경로를 보여 준다.

## 1. 실제 기록과 시연 데이터 분리
- 실제 모드의 점수 집계·연속 기록은 실제 유효 트립만 쓴다. `DemoData.trips`를 섞지 않는다.
- 각본 주행 트립은 `trips.json`에 저장하지 않는다. 결과 화면 표시는 지금처럼 동작해야 한다.
- 실제 트립의 경로가 비면 가상 경로 대신 경로 없이 보여 준다.

## 2. 순위 계산 (순수 함수, 테스트 먼저)
- `core/calculator/`에 순수 함수를 둔다. 입력은 내 실제 트립, 오늘 날짜, 티어이고 출력은 내 순위, 시즌 평균, 승급 라인까지 남은 계단과 점수, 위아래 이웃이다.
- 시즌은 `LocalDate` 기준 이번 달 1일~말일. 이번 시즌 유효 트립만 평균에 넣는다.
- 다른 운전자는 가상 396명으로 고정 생성한다. 실행마다 값이 달라지면 안 된다(난수 금지). 별명은 기존 가상 별명 방식으로, 실명처럼 보이는 이름은 쓰지 않는다.
- 평균 분포는 브론즈 기준 약 60~88점으로 잡고, 값은 `DemoData` 옆에 시연용 가상값이라고 주석을 단다.
- 승급·강등 라인은 기존 `promotionRank`, `demotionRank`를 재사용한다.
- 테스트: 평균이 오르면 순위가 오른다, 동점 처리, 1등·꼴찌 경계, 3km 미만 트립 제외, 지난달 트립 제외, 트립 0개, 같은 입력이면 같은 결과.

## 3. 화면 연결
- 실제 트립 결과 카드: 순위, ▲▼ 변화(이번 트립을 넣기 전후 비교), 승급 라인, 이웃 줄, 점수 차 문구를 계산값으로 쓴다.
- 리그 화면: 시연 화면을 보는 중이 아니면 계산값을 쓴다. 제목은 이번 달과 내 티어, 첫 번째 탭은 내 차종.
- 실제 트립이 0개면 순위 대신 「첫 주행을 마치면 순위가 나와요」를 보여 준다. 가짜 순위를 보여 주지 않는다.
- 금액·급제동 감소 같은 리그 효용 수치는 가상값이므로 실제 모드에서는 숨긴다.
- 이번 범위 밖: 주간 리포트 실데이터, 지역·친구 탭 동작, 시즌 종료 시 티어 이동. 다음 작업에서 한다.

## 4. 차종 인식
- Pleos `CarInfo`는 VIN만 준다. **VIN은 읽지도 저장하지도 않는다.** `Build.MODEL`도 쓰지 않는다(에뮬레이터에서 「Connect on x86_64 emulator」).
- `CarPropertyManager`로 `INFO_MAKE`, `INFO_MODEL`, `INFO_FUEL_TYPE`을 한 번 읽는다. 지원 안 함·권한 없음·오류는 앱이 죽지 않고 미인식으로 처리한다.
- 순수 함수로 판정한다: 읽은 값이 지원 차종 목록과 일치할 때만 인식 성공. 빈 값, 에뮬레이터 기본값, 목록 밖 값은 전부 미인식이다.
- 지원 차종 목록: 현대·기아·제네시스 주요 차종 10개 안팎, 각 차종의 동력(EV/내연기관) 포함. 아이오닉 5를 넣는다.
- 동력은 `INFO_FUEL_TYPE`이 있으면 그 값(ELECTRIC이면 EV), 없으면 목록 값을 쓴다.
- 결과는 SharedPreferences에 차종명·동력·티어·인식 방식만 저장한다.
- 에코 기준값: EV는 기존 `leagueAvgEfficiency`, 내연기관은 가상 평균 연비 상수를 새로 두고 `TripCollector`에 프로필에 맞는 값을 넘긴다. 프로필이 바뀌면 다음 트립부터 적용한다.
- 리그 구분 키는 차종+동력이다.
- 테스트: 일치, 대소문자·공백 차이, 빈 값, 기본값, 목록 밖, 동력 결정.

## 5. 새 화면 2개
`Screen`에 추가한다. 기존 `view_*.xml` + `DesignCanvas` 1280×720 방식, 색과 글꼴은 `mockups/tokens.css` 기준. 글씨 24sp 이상, 터치 76dp 이상, 이모지 금지, 빨강 금지.

**차종 선택** (인식 실패 때, 또는 차종 변경 때)
- 제목 「어떤 차로 달리시나요?」, 설명 「같은 차종 운전자끼리 겨뤄요」.
- 지원 차종을 큰 버튼 격자로 보여 준다. 마지막에 「기타 차종」: 이름 입력 + EV/내연기관 선택.
- 기타 차종의 이름은 앞뒤 공백을 없애고 빈 값은 막는다. 길이는 20자까지.

**리그 배치**
- 위 작은 글씨: 「2026년 11월 시즌」처럼 이번 달.
- 큰 글씨 2줄: 「{차종} 리그」, 「브론즈 단계에 배치되었습니다」.
- 레이스 엔지니어 얼굴과 팀 라디오 한 줄: 「첫 레이스를 시작해 볼까요?」.
- 버튼: 「시작하기」(주 버튼), 「차종 변경」. 자동 인식이었다면 작은 글씨로 「차량 정보로 확인했어요」를 넣는다.
- 브론즈 색은 `tokens.css`와 `colors.xml`에 토큰 하나를 추가해 쓴다.

**흐름**
- 프로필이 없으면 시작 때: 인식 성공 → 배치 화면, 실패 → 차종 선택 → 배치 화면.
- 시작하기를 누르면 기존 첫 화면으로 간다. 프로필이 있으면 두 화면 모두 건너뛴다.
- 리그 화면의 차종 탭을 누르면 차종 선택으로 간다. 변경해도 티어와 트립 기록은 유지한다.
- 주행 제한이 걸리면 두 화면도 주행 중 화면에 자리를 내준다. 키보드 입력은 정차 중에만 된다. 제한이 풀리면 프로필이 없을 때 선택 화면으로 돌아온다.
- 시연 바에 「배치」 탭을 추가해서 배치 화면을 바로 볼 수 있게 한다.

## 6. 검증
- 항목마다 `.\gradlew.bat testDebugUnitTest assembleDebug -q` 통과 후 커밋 하나.
- 에뮬레이터는 이미 켜져 있다. 끄지 말고 쓴다. 앱 데이터를 지워 첫 실행을 재현한다. 시스템 설정은 바꾸지 않는다.
- `INFO_MAKE`, `INFO_MODEL`, `INFO_FUEL_TYPE`의 실제 읽기 결과를 Logcat으로 확인해 로그에 적는다.
- 첫 실행 흐름 캡처: `captures/league-real-score/`에 차종 선택, 기타 차종 입력, 배치 화면.
- Virtual Console(`adb forward tcp:8088 tcp:8088`, http://127.0.0.1:8088/)로 3km 이상 두 번 달려 순위가 바뀌는 것을 확인하고 결과 카드·리그 화면을 캡처한다. 브라우저 자동화가 막히면 그 이유를 로그에 적고, 순위 변화는 단위 테스트 근거로 남긴다.
- 시연 모드 92점·64점 화면이 그대로인지 캡처로 확인한다. 각본 주행 뒤 `trips.json`에 트립이 늘지 않는지 확인한다.
- 재시작 후 프로필과 순위 유지 확인. 주행 중 화면에 점수·순위가 없는지 확인.
