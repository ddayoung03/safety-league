# 앱 개발 인수인계 (Antigravity용)

이 문서를 먼저 다 읽고 작업을 시작해라. 기준 문서는 아래 셋이다.
- 설계 문서: `docs/superpowers/specs/2026-11-03-screen-mockups-design.md` (화면·숫자·규칙의 기준)
- 화면 시안: `mockups/*.html`, `mockups/png/*.png` (그대로 옮길 디자인)
- 점수·연속 기록·리그 규칙과 테스트: `mockups/demo-data.js`, `mockups/test/demo-data.test.js`

## 만들 것
Pleos Connect(Android Automotive OS) 앱 "세이프티 리그". 실제 차량 신호로 트립마다 안전 운전 점수(100점)를 매기고,
같은 차종 운전자끼리 월간 시즌 리그로 겨룬다. 본선은 12/3~4 Pleos Connect 에뮬레이터 + Virtual Console 시연.

## 꼭 지킬 규칙
- 점수 = 부드러움 30 · 매너 25 · 에코 20 · 안전 기본기 15 · 꾸준함 10. 10km당 환산, 3km 미만 트립 제외, EV/내연기관 리그 분리.
- 연속 안전 주행: 트립 70점 이상이면 이어지고, 그날 트립 하나라도 70점 미만이면 끊김. 운전 안 한 날은 건너뜀.
- 리그: 월간 시즌, 브론즈~다이아. 시즌 끝에 같은 티어 안 상위 30% 승급, 하위 30% 강등.
- 결과 카드는 GEAR_SELECTION이 P로 바뀔 때 표시. 주행 중에는 CarUxRestrictionsManager를 따르고 점수·순위·감점 화면 금지, 수집만.
- 레이스 리플레이: 주행 경로(위치 기록) 위에 급제동·급가속·깜빡이 없는 차선 변경 지점. 경로는 본인 화면에만, 리그 공유 금지. 사건별 감점 숫자 표시 금지.
- 가독성(Android Automotive 가이드): 글씨 24dp 이상, 대비 4.5:1 이상, 누르는 영역 76×76dp 이상, 어두운 테마.
- 색·글꼴: `mockups/tokens.css` 그대로 (아스팔트 #24272C, 노랑 #FFC52E, 빨강 #C8102E, Black Han Sans + Saira Condensed).
- 리그 순위는 시연용 가상 운전자 데이터. 실명·연락처·이메일·소속을 코드·커밋·화면에 넣지 않는다.

## 작업 방식
1. 점수 계산은 순수 함수(Kotlin)로 분리하고, 테스트를 먼저 쓴다. `mockups/test/demo-data.test.js`의 케이스를 Kotlin 단위 테스트로 그대로 옮겨 같은 결과가 나와야 한다 (시즌 평균 88.5/88.8, 연속 기록 12/13/15/11/0, 승급 라인 P119, 강등 P279 등).
2. 버그는 증상이 아니라 원인을 고친다. 고치기 전에 재현 테스트부터.
3. 작업은 `app` 브랜치에서 하고, 작은 단위로 커밋한다. `main`에 합치거나 push하지 않는다.
4. 하루 작업이 끝나면 `docs/app-dev-log.md`에 날짜별로 적는다: 한 일, 막힌 점, 직접 정한 것(이유 포함), 확인 못 한 것.

## 먼저 할 일 (순서대로)
1. Pleos Connect SDK·에뮬레이터 환경 확인: Vehicle State SDK(속도·브레이크·조향각·방향지시등·안전벨트·경고등·도어·주행거리·EV/연료), NaviHelper, 위치 정보를 실제로 받을 수 있는지. 결과를 로그에 적는다. 기획서와 다르면 표시한다.
2. AAOS 앱 프로젝트 뼈대 (Kotlin, 최소 SDK는 Pleos 문서 기준).
3. 점수·연속 기록·리그 규칙 순수 함수 + 단위 테스트.
4. 차량 신호 수집 (백그라운드) → 트립 기록.
5. 화면: 결과 카드 → 레이스 리플레이 → 리그 → 주간 리포트 → 주행 중 화면 순.
